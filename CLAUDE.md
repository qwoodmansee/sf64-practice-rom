# Star Fox 64 Practice ROM — AI Agent Rules

## CRITICAL: Never run `make clean` or `make init`

These commands delete generated asset headers (`include/assets/*.h`) and linker
scripts that take 10+ minutes to regenerate from the base ROM. There is almost
never a reason to run them during development.

- **To rebuild from scratch:** `rm -rf build/ && make practice -j4`
  This removes compiled objects only. Asset headers and extracted files are preserved.
- **To do an incremental build:** `make practice -j4`

If you absolutely must run `make init` or `make extract` (you probably don't),
the linker script patch runs automatically afterward via
`tools/patch_linker_script.py`. But the full asset regeneration will still take
a very long time.

## Build commands

| Command | Purpose |
|---------|---------|
| `make practice -j4` | Build the practice ROM (incremental, fast) |
| `rm -rf build/ && make practice -j4` | Full rebuild without touching assets (~15s) |

Always build with `make practice`, never plain `make`. Plain `make` builds the
vanilla ROM without `PRACTICE_ROM=1` and the practice code will be compiled out.

## Linker script

`linker_scripts/us/rev1/starfox64.ld` is gitignored (generated by splat).
Practice ROM `.o` files must be listed in its `.text`, `.data`, `.rodata`, and
`.bss` sections. This is handled automatically by:

- `tools/patch_linker_script.py` — runs after `make extract` and before
  `make practice`
- If you add a new practice source file, add it to `PRACTICE_OBJS` in that
  script **and** to `src/practice/` in the Makefile's source discovery

## Architecture

All practice ROM code lives behind `#ifdef PRACTICE_ROM` guards:
- `include/practice.h` — public API and shared types
- `src/practice/` — all practice-specific source files
- `src/engine/fox_game.c` — hooks to call `Practice_Init/Update/Draw`
- `src/engine/fox_play.c` — cutscene skip logic in `#ifdef PRACTICE_ROM` blocks

## Code style

This is a C codebase targeting the N64 (MIPS). Use the project's existing
conventions: `gCamelCase` for globals, `sCamelCase` for file statics,
`PascalCase` for types, `UPPER_CASE` for defines/enums. Use `bcopy(src, dst, len)`
instead of `memcpy` — it's the N64 SDK equivalent.
